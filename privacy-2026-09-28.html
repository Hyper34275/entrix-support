PART II — PRIVACY POLICY

Privacy Policy version 2026-09-28. This Privacy Policy describes how Entrix handles personal data in the iPhone app, Windows components, backend service, subscription system, security systems and related support interactions. It reflects the implementation verified as of 28 September 2026.

1. Controller and contact

The operator and controller of Entrix is Amos Yuval Samya, an individual operating from Israel. Privacy questions and rights requests may be sent to entrixsupport@gmail.com. This document does not publish a residential address. Where applicable law independently requires additional identification or address information, the Operator remains responsible for satisfying that requirement.

2. Scope and storage model

Entrix deliberately splits information among the self-hosted Entrix server, Supabase authentication, the local Windows PC and the local iPhone. Some security secrets are never available to the backend in plaintext. The categories below describe current processing and should be read together with the retention table and provider table.

4. Legal acceptance records

For each iPhone acceptance, the legal_acceptances record contains the account ID, Terms version, Privacy version, SHA-256 fingerprint of each published document, app build, and UTC acceptance time. Older acceptance records may remain as history while the account exists and are deleted with the account. The document fingerprints are used to help ensure that the text accepted under a version has not silently changed.

5. Supabase — sign-in session service

Supabase processes the Apple user identifier, the e-mail address Apple provides (which may be an Apple private-relay address), and sign-in timestamps/session information. The Entrix self-hosted application database does not store the account e-mail address as its primary account data. The current Supabase project is hosted in AWS region ap-northeast-1 (Tokyo, Japan).

6. Data stored locally on the Windows PC

  • Per Windows user: sign-in profile data including TOTP secret, recovery-code hash, password verifier and approved phone names; app configuration including TOTP secret, recovery code and synchronization key; and the optional TPM-protected PIN Vault.

  • For the whole PC: machine credential, signed entitlement token, protection settings, the Microsoft-account e-mail of protected users where needed by the protection configuration, local legal-acceptance record and diagnostic logs.

  • Local state is protected by Windows DPAPI and/or folder permissions restricted to SYSTEM and Administrators as applicable. The PIN Vault additionally uses TPM-backed protection.

  • Windows diagnostic logging redacts e-mail addresses and user-profile paths, removes Windows user names from the relevant log sites, and represents SIDs only as short one-way hashes. The machine-wide log folder is readable only by SYSTEM and Administrators.

7. Data stored locally on the iPhone

The iPhone Keychain and local app storage may contain pairing keys, synchronized TOTP and recovery material, the Entrix account identifier and cached settings. These local items support pairing, recovery and app operation. The iPhone can display computer names and security state in the app and, depending on notification settings, on the Lock Screen or Dynamic Island.

8. Biometrics

Entrix does not receive your face, fingerprint, Face ID template, Touch ID template or biometric measurements. Apple iOS performs the biometric comparison and returns a local result. The Entrix backend receives only the approval or denial action that follows; it does not receive biometric data.

9. Windows credentials and encrypted synchronization

A Windows password entered into the Entrix Credential Provider is processed locally so it can be supplied to Windows. It is not transmitted to the Entrix backend or iPhone. If PIN Vault is enabled, an encrypted copy is retained locally under TPM-backed protection. TOTP and recovery synchronization between paired PC and iPhone is end-to-end encrypted; the backend stores ciphertext and does not possess the decryption key.

17. Account deletion

Account deletion starts in the iPhone app at Settings → Delete Account and requires a fresh Sign in with Apple from the same Apple ID. A mismatched Apple ID is refused. Once confirmed, the server deletes the Entrix account and account-linked server data, revokes the relevant Apple sign-in authorization where supported, deletes the Supabase sign-in user, and releases each paired PC.

When a released PC next comes online, it normally erases that Windows user's Entrix sign-in profile, TOTP secret, recovery code, PIN Vault, sync key, stored account e-mail and protection settings, then returns to normal Windows sign-in behavior. A PC that remains offline can keep that local data until it reconnects or Entrix is uninstalled. Backup copies containing deleted data expire within 30 days. A deletion marker containing only account ID and deletion time remains for 90 days to stop stale credentials from recreating the account.

Deleting the Entrix account does not cancel an Apple subscription. The user must separately manage or cancel the subscription through Apple. Removing a single computer from the iPhone app releases that computer using the same general cleanup approach.

19. Windows logs and diagnostics

Windows logs are local to the PC and are not automatically uploaded to Entrix. Current logging is designed to redact e-mail addresses and user-profile paths, omit Windows user names from relevant log sites, and show only a short one-way hash for SIDs. Exceptions are logged without source paths and with personal data redacted from messages where supported. The machine-wide log folder is restricted to SYSTEM and Administrators. If you voluntarily send a log to support, the Operator will process what you provide for support/security purposes.

20. Lock Screen and notification exposure

Push notifications and Live Activities can display a computer name, event type, request/machine identifier, security status or attempt count on the iPhone Lock Screen or Dynamic Island, depending on iOS notification-preview settings. Users who do not want those details visible on a locked phone should configure Apple's notification preview settings accordingly.

Entrix is not intended for children under 16 and does not knowingly offer child accounts. The App Store 4+ label is a content-suitability rating and is separate from the service eligibility rule. Entrix does not currently collect a date of birth or perform an independent age check. If the Operator learns that an under-16 user has created an account, the situation may be reviewed and appropriate action taken under applicable law.

22. Security measures

Entrix uses layered technical and organizational controls intended to reduce risk. These measures do not guarantee absolute security, but the current implementation includes:

  • TLS for app-to-service transport; the self-hosted origin listens locally behind the Cloudflare tunnel.

  • End-to-end encryption for synchronized TOTP secrets and recovery codes; the backend holds ciphertext only.

  • Apple App Attest on authenticated iPhone account requests; development-build App Attest keys are refused in production.

  • Face ID for Windows sign-in approvals; the phone passcode is not accepted as the approval factor.

  • TPM-backed protection for the optional Windows PIN Vault and Windows DPAPI/restricted folders for local secret state.

  • A local named pipe that accepts only permitted interactive users, SYSTEM and Administrators; network logons are denied.

  • Random 256-bit machine credentials stored server-side only as scrypt hashes, least-privilege database access, ownership checks on routes, and rate limiting by relevant IP/account/computer context.

  • Single-use approval, pairing, Windows Hello and App Attest challenges where designed as one-time operations.

  • Security-alert push throttling, expiry checks for remote commands, and certificate-chain verification of App Store server notifications.

  • Log-redaction tests, restricted Windows log permissions, fixed Windows log retention, and key-revocation/rotation procedures.

23. Backups

The Operator creates encrypted daily backups of the database and server configuration. Current backup retention is 7 days on the server and 30 days off-site in Google Drive. The backup encryption key is held by the Operator and is not stored on the server or by Google. A full restore has been tested. Deleted account data can remain inside backup copies until the applicable backup expires, but ordinarily leaves all current backup sets within 30 days.

24. Secrets, rotation and emergency revocation

Private keys are not intended to be kept in the source tree. Production secrets are stored in a root-owned server location. Entrix maintains a rotation procedure covering revoke → rotate → deploy → invalidate, and an emergency mechanism can revoke one computer credential, all computer credentials for an account, or all computer credentials. Windows clients support a second entitlement signing-key identifier so a signing key can be rotated without reinstalling the client.
